# Перенос аккаунтов через Google Drive

## Прямое подключение Google Drive

В настройках нажмите **Подключить Google Drive** и разрешите доступ в системном браузере. Это требуется один раз на каждом устройстве. Приложение запрашивает только `drive.appdata`: доступ к собственной закрытой папке, без доступа к остальным файлам диска.

Для сохранения введите мастер-пароль и повторите его, затем нажмите **Сохранить в Google Drive**. Для загрузки на другом устройстве подключите тот же Google-аккаунт, введите мастер-пароль и нажмите **Загрузить из Google Drive**. Приложение само скачает последнее сохранение и добавит профили. Выбирать файл или устанавливать клиент Google Drive не нужно.

Перед сохранением обновите входы в профилях приложения. Сохраняется снимок профилей; фонового обновления облака нет. Каждое сохранение создаёт отдельную резервную копию. Повторная загрузка создаёт копии профилей. Если последний архив зашифрован другим паролем, нужен пароль именно от него. Старые копии в облаке автоматически не удаляются.

Вход Google защищён Electron safeStorage (Windows DPAPI или системное хранилище Linux); открытое хранение на Linux запрещено. Мастер-пароль не сохраняется. **Отключить Google Drive** удаляет локальный токен, но не удаляет резервные копии и не отзывает разрешение Google; разрешение можно отозвать в настройках Google-аккаунта.

### Настройка для разработчика

Для работы прямого подключения сборке нужен OAuth-клиент Google типа Desktop app с включённым Google Drive API. Зарегистрируйте приложение в Google Cloud, настройте экран согласия и аудиторию, скачайте JSON клиента в `desktop/build/google-oauth.json` (файл исключён из Git). Для сборки в GitHub Actions сохраните этот JSON в секрете репозитория `GOOGLE_OAUTH_CLIENT_JSON`. Сборка включает его в `resources/google-oauth.json`. Один и тот же клиент должен использоваться на устройствах, между которыми переносятся профили.

Пример структуры: `desktop/build/google-oauth.example.json`. При отсутствии настроек кнопка подключения недоступна. В режиме Google Testing нужно добавить свой Google-аккаунт в тестовых пользователей; ограничения длительности разрешений и выпуска проверяйте в консоли Google перед распространением приложения.

Авторизация использует PKCE S256, случайный state и временный HTTP callback только на `127.0.0.1`. Токены и ответы ошибок Google не отправляются renderer-процессу. При сетевых ошибках импорт не начинается, текущий вход остаётся на месте. Перед удалением временных файлов в них находятся только зашифрованные архивы.

Документация: [OAuth для настольных приложений](https://developers.google.com/identity/protocols/oauth2/native-app), [закрытая папка приложения](https://developers.google.com/workspace/drive/api/guides/appdata).

## Резервный перенос через файл

В дополнительных настройках **Перенос через файл** доступны экспорт и импорт зашифрованного архива.

1. Сохраните актуальные входы в профили приложения. Для пустых профилей сначала сохраните вход или удалите их.
2. В настройках введите мастер-пароль от 12 символов и повторите его.
3. Нажмите **Экспорт файла** и выберите синхронизируемую папку Google Drive для компьютера. Можно выбрать обычную папку и затем вручную загрузить файл на https://drive.google.com.
4. Дождитесь завершения загрузки файла клиентом Google Drive.
5. На новом устройстве установите Codex Accounts, выберите Codex Home, скачайте архив из своего Google Drive, введите мастер-пароль и нажмите **Импорт файла**. Выберите файл `.encrypted`.

Каждое сохранение создаёт отдельный файл с датой и уникальным идентификатором. Импорт добавляет новые профили; повторный импорт создаёт копии. Текущий вход Codex и существующие профили не заменяются. На Ubuntu архив можно скачивать и загружать через браузер.

В архив входят названия профилей и сохранённые данные авторизации. История чатов, проекты, настройки и ключи системного хранилища не переносятся. После импорта входы защищаются локальным хранилищем Windows или Ubuntu. Устаревший либо отозванный вход потребует повторной авторизации. Одновременную работу копий одной сессии на разных устройствах нужно проверить отдельно.

Формат CAAR1: PBKDF2-HMAC-SHA256 (600 000 итераций, случайная соль 16 байт), AES-256-GCM (случайный nonce 12 байт, tag 16 байт); заголовок аутентифицируется. Пароль не сохраняется и не отправляется в Google Drive. Без пароля архив не восстановить. Архив вместе с паролем даёт доступ к сохранённым входам. Не добавляйте архивы в Git или публичные ссылки.

Успешное сохранение подтверждает запись локального файла, а не завершение синхронизации Google Drive. Автоматической синхронизации и объединения обновлённых токенов в этой версии нет.
